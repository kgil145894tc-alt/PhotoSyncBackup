# Logout to Login

The root navigator owns login and logout transitions through Expo Router's `Stack.Protected`. One root auth subscription resolves the account role and enables either the Client or Admin navigator. Guest routes are disabled after login; protected routes and their history are removed after logout, with `/login` as the fallback. The Client navigator starts at `/home`. Password recovery remains accessible with or without a session.

Profile handlers close the logout confirmation before starting sign-out and leave navigation to the root guard. The login form also leaves successful auth navigation to the guard, and ignores async completions after unmount. Nested navigators no longer replace their entire tree with an auth-loading screen during sign-out. These changes address competing native navigation/mount operations observed in the login → logout → login flow. The Android Fabric `addViewAt` stack trace alone does not identify the failing view; device reproduction is still needed to confirm the native crash is resolved.

`signOutPhotoSync` attempts notification cleanup for at most 2.5 seconds, cancels an unfinished request, and continues sign-out if cleanup fails. Cleanup uses the captured session credentials and never requests notification permission or a new Expo token. The existing Supabase sign-out scope is retained. A genuine auth sign-out error still throws: each Profile shows a failure notice, releases its loading state, and stays on its current route for retry. Account caches clear through their existing auth subscriptions when the session ends.

Push registrations are tied to `auth.sessions.id`. Successful server sign-out removes their session and cascades deletion of its push registrations, even when device cleanup fails. Registration validates and locks its session so a late request cannot recreate a logged-out registration. Explicit cleanup removes only its own session; it cannot remove another device or a newer login. The push sender reads only active, matching sessions through a service-role-only RPC. Foreground display, notification taps, and inbox invalidation require the payload's recipient to match the current account. Sign-out also clears existing notification responses and dismisses presented notifications.

Deploy `docs/supabase-push-notifications.sql` before the updated `send-push-notification` Edge Function. Older registrations have no session binding and are excluded from delivery until the device registers again when its protected layout mounts; reopen the app or log in again after deployment. Pushes already submitted to Expo before sign-out can still arrive, especially while the app is in the background. This change does not recall messages already queued by the operating system.

The root auth hook invalidates pending role checks on sign-out or account changes. Auth SDK reads run outside the synchronous auth callback. Initial session restoration hides all routes until the role is known; subsequent auth changes retain the root navigator. A new login rechecks authorization; repeated sign-in events for the same account and token refreshes do not add role queries or disturb the mounted stack. Unmount unsubscribes, and logout/unmount cancels queued login checks.

Auth regression tests exercise Expo Router's bundled stack router to verify that logout removes protected history, Back cannot restore it, and re-login creates a fresh navigator. Hook tests cover out-of-order role reads, account changes, initial loading, failed checks, and subscription cleanup. Form tests cover late login/reset-email results after unmount, and both profiles retain sign-out failure/retry checks.

Validation: logout service and both Profile handlers have success, failure, retry, and late-completion tests. Push tests cover cleanup cancellation, account switching during registration, recipient filtering, inactive-session delivery, and bootstrap completion after unmount.
